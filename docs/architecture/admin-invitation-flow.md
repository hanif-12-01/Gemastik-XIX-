# Admin Invitation Registration Flow

## 1. Security Principle
Public Admin self-registration is strictly prohibited. New Admin accounts can only be created via single-use, time-bound invitation tokens generated by an active Super Admin.

## 2. Sequence Diagram & Flow
```text
Authenticated Admin → POST /api/v1/auth/admin/invitations { email }
  ├── Generates 32-byte crypto random raw token
  ├── Computes SHA-256 tokenHash
  ├── Stores record in `admin_invitations` table with 24-hour expiry
  └── Returns invitation URL (/auth/admin/invite/:token)

Invited User → Opens /auth/admin/invite/:token
  ├── Frontend calls GET /api/v1/auth/admin/invitations/:token/validate
  ├── Backend verifies token exists, hash matches, unused (usedAt IS NULL), and not expired
  ├── User enters password and name
  └── Frontend calls POST /api/v1/auth/admin/invitations/:token/register
        ├── Backend verifies token again
        ├── Creates User with role = admin
        ├── Marks invitation usedAt = NOW()
        └── Writes AuditLog (REGISTER_ADMIN_INVITATION)
```

## 3. Entropy & Protection
- Token entropy: 32 bytes (64 hex characters) from `crypto.randomBytes(32)`.
- Database storage: Only SHA-256 `tokenHash` is saved in the DB, preventing token theft from database backups.
